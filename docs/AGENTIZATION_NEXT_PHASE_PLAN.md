# ProductionRun 下一阶段 Agent 化计划（M8–M12）

状态：M7 发布候选之后的实施基线
制定日期：2026-08-26

## 1. 当前基线

M1–M7 已完成可恢复、可审计的 ProductionRun v1 控制面。当前能力边界如下：

- 分镜主管 Agent 已成为 `storyboard` 和 `pipeline` 的默认分镜引擎，并通过 M7 固定样本、跨平台工程验收和 19 组人工盲评；
- 图像主管 Agent 已具备规划、审批、授权、质量门、修复和恢复能力，但尚未完成与分镜同等级的固定视觉集和独立人工盲评，因此媒体阶段和旧 CLI 图像 Agent 仍为显式启用；
- 配音导演具备受限 LangGraph 阶段，现有验收主要使用确定性模型端口，尚未证明真实模型的导演质量；
- TTS 和视频 Provider 路径已经具备真实调用、预算、结算、恢复和审计能力，但它们是受控执行器，不是 Agent；
- 顶层 reducer、DAG、锁、预算、审批、授权、结算和事件链保持确定性，并继续作为唯一状态权威。

因此，下一阶段目标不是让所有代码都由模型控制，而是让需要语义、审美和修订判断的创作层逐步 Agent 化，同时保持安全控制层确定性。

## 2. 总目标与不可突破边界

目标是交付“创作层 Agent + 确定性控制面”的完整素材生产系统：用户提交源文本后，系统自动推进到正确终点或明确的人工门，并能解释停止原因、修订影响、预计费用和下一步操作。

优先级按以下顺序执行：

1. 来源忠实性、角色与时序一致性；
2. 未授权零付费、未知结果零自动重试、恢复零重复提交；
3. 输出可制作性和跨媒体连续性；
4. 正确完成率和正确人工门命中率；
5. 成本、时延和模型调用次数。

以下权力不得交给 Agent：

- 批准费用或扩大授权范围；
- 将未知 Provider 结果推断为成功或失败；
- 绕过人工质量门、预算、版本绑定或完整性失败；
- 直接改写顶层事件账本、结算记录或已发布产物；
- 自行读取凭据、改变 Provider profile 或降低安全策略。

## 3. M8：图像 Agent 质量发布

当前状态（2026-08-27）：固定 20 故事/60 场景组的评测合同、匿名材料生成器、三评委评分校验、解盲汇总器和 ProductionRun HMAC/current-head 可信证据边界已经实施并完成离线测试；Windows 为 626 passed/13 skipped，Linux 为 631 passed/8 skipped/16 subtests passed，三轮独立 Sol 复验均关闭 P0/P1。合同与复现命令见 [`docs/PRODUCTION_RUN_M8_VISUAL_QUALITY_CONTRACT.md`](PRODUCTION_RUN_M8_VISUAL_QUALITY_CONTRACT.md)。真实双引擎图像证据、真实低额度 API 和三人视觉盲评仍未完成，因此 M8 尚未通过，图像默认值不变，也不能进入 M9。

### 目标

把图像 Agent 从“工程闭环可用”提升到“视觉质量可验证”，通过后才能考虑成为新项目的推荐图像引擎。图像生成是否执行仍由用户显式启用，真实付费仍需要审批和 grant。

### 实施

- 冻结不少于 20 个故事、60 个场景组的视觉评测集，覆盖多人、重复角色名、跨场景服装、关键道具、昼夜变化、动作连续性和复杂构图；
- 保存角色身份卡、场景母版、镜头输入、候选图、修订轨迹、视觉审核证据和费用记录；
- 引入真实视觉模型复核端口，未配置时明确停在人工门，不得以规则检查冒充视觉验收；
- 将角色、服装、道具、空间、动作和画幅问题映射到可定位的 repair plan；
- 验证局部修订只失效受影响图像，不重复无关付费调用。

### 发布门槛

- 结构、审批、授权、预算、恢复和防重复提交测试 100% 通过；
- 相对当前 legacy 图像路径，人工盲评综合偏好不低于 60%；
- 角色一致性和来源忠实性不得低于 legacy，严重语义错误不得多于 legacy；
- 所有真实调用均在批准范围和预算内，`outcome_unknown` 不自动重试；
- Windows/Linux 全量回归通过；
- 三轮独立红队复验全部关闭高优先级问题。

## 4. M9：真实配音导演 Agent

### 目标

将 M4.1 的确定性模型端口升级为可配置的真实配音导演 Agent。Agent 只决定角色声音需求、情绪、语速、停连、重音和修订建议；speaker/cue 身份、付费 TTS 提交和结算继续由确定性代码控制。

### 实施

- 冻结不少于 20 个项目、60 个配音 cue 的评测集，覆盖独白、多人对白、无对白、旁白、情绪反转和未解析说话人；
- 为每个导演判断绑定 storyboard、voice script 和原文证据；
- 建立真实模型失败、非法结构、证据不足、调用超限和恢复测试；
- 补齐多角色实际 voice 请求、voice map、逐 cue 回执和可听样本证据；
- 产出可供盲听的匿名 A/B 包，对比确定性基线。

### 发布门槛

- cue 和 speaker 一一对应，未解析说话人必须进入人工门；
- 不增加原文不存在的对白、角色或剧情事实；
- 人工盲听综合偏好不低于 60%，来源忠实性不得退步；
- 多音色、恰一次提交、结算和恢复证据完整；
- 三轮独立红队复验通过后，真实导演 Agent 才能从实验配置升级为推荐配置。

## 5. M10：视频创作主管 Agent

### 目标

新增视频创作主管 Agent，负责运动设计、镜头时长、镜头间连续性、参考图选择、视频提示词审计和失败修订。Provider 调用、轮询、结算与发布继续由确定性三阶段执行器负责。

### 实施

- 建立 `video_direction` 权威产物，绑定 storyboard、已批准图像、时序状态和原文证据；
- Agent 只能提交结构化生成建议或 repair plan，不能直接调用付费 Provider；
- 覆盖人物漂移、道具消失、动作跳变、运镜冲突、画幅错误、首尾帧不一致和 Provider 拒绝；
- 支持只重做受影响视频，不重做已批准图像、配音或无关镜头；
- 形成匿名视频 A/B 包，由内容、制作和普通观众三个视角独立评审。

### 发布门槛

- 相对确定性 video prompt 基线，盲评综合偏好不低于 60%；
- 来源忠实性、角色连续性和镜头可用性不得退步；
- 真实任务提交、轮询、未知结果对账和恢复均不重复计费；
- 所有修订都有影响分析、版本绑定和审计证据；
- 三轮独立红队复验通过。

## 6. M11：跨媒体创作监督与一键入口

### 目标

让用户不再判断内部命令顺序。增加一个高层入口，自动推进分镜、图像、配音和视频，直到完成、等待审批、需要人工判断或外部条件阻塞。CLI 保留为恢复和运维接口，前端复用相同的 ProductionService DTO。

### 实施

- 增加跨媒体创作监督层，只负责解释质量问题、提出修订范围和协调创作 Agent；
- 顶层 DAG 仍决定哪些节点可运行，监督 Agent 不拥有状态转换权；
- 提供单一运行入口、稳定状态摘要、费用预估、审批清单和下一步说明；
- 验证分镜变化对图像、配音、视频的选择性失效，避免全量重做；
- 为桌面或网页界面冻结无路径 DTO 和操作合同。

### 发布门槛

- 固定矩阵中至少 95% 项目到达正确终点或正确人工门；
- 用户无需理解子 run、内部文件或恢复命令；
- 任意 Agent 失败都能返回稳定原因码、证据和安全下一步；
- 费用、审批、调用和版本状态与底层审计账本一致。

## 7. M12：全创作链发布验收

M12 不以“所有阶段都是 Agent”为通过条件，而以“所有创作判断都有经过验证的 Agent，所有高风险操作都有确定性权威”为通过条件。

最终验收包括：

- 固定文本、图像、配音和视频评测矩阵；
- 图像盲评、配音盲听、视频盲评和跨媒体连续性评审；
- 至少 5 个低额度真实 API 端到端项目；
- Windows/Linux 的恢复、锁、路径、篡改和打包验证；
- 所有崩溃窗口、未知结果、重复提交、预算越界和凭据脱敏测试；
- Luna-Max 以节约 token 方式执行实现与修复；
- 每个有代码或合同改动的里程碑完成后，由 Sol-Medium 进行三轮相互独立的红队测试；
- 只有全部高优先级问题关闭后，才变更默认配置和对外能力声明。

## 8. 执行顺序与停止规则

严格按 `M8 → M9 → M10 → M11 → M12` 推进。每个里程碑都必须按“冻结合同与样本 → 实施 → 本地回归 → 真实低额度测试 → 人工盲评 → 三轮独立红队 → 修复后复验 → 保存证据与提交”执行。

出现以下任一情况时停止自动推进并生成人工测试说明：

- 需要真人判断图像、声音或视频的审美质量；
- 需要用户批准真实费用、提供账号或完成外部平台操作；
- 真实 Provider 返回无法自动确认的结果；
- 评测结论会改变默认引擎、成本上限或产品范围；
- 三轮红队后仍存在未关闭的高优先级问题。
