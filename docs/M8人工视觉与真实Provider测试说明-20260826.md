# M8 人工视觉与真实 Provider 测试说明（2026-08-26）

## 当前停止点

离线评测合同、20 故事/60 场景组清单、逐组证据校验、匿名 A/B 打包和三评委汇总已实现。
AI 不能代替真人判断图像审美，也不能替用户批准真实付费 Provider，因此正式 M8 在此停止。
在下列步骤全部完成前，不得把图像 Agent 改为默认路径，也不得声称 M8 或正式发布通过。

## 一、先准备可审计的 60 组真实候选

1. 使用 `m8_evaluation/samples.json` 的 20 个故事和 60 个固定 `group_id`，为每组选择真实
   storyboard/镜头输入。不得用任意文本、重复占位图或 M7 历史盲评结果替代。
2. Agent 与 legacy 两侧必须使用相同来源、storyboard、画幅、参考图和场景组范围；差异只能是
   被比较的生成路径。
3. Agent 侧必须从受控 ProductionRun/图像 Agent v4 运行产生，并保留：来源或 storyboard
   绑定、角色身份卡、scene master、镜头输入、候选图、修订轨迹、自动视觉审核、费用或零成本
   fixture 记录。运行必须是 `completed`，自动视觉审核完成，`passed_without_override=true`，
   `manual_quality_override=false`，阻塞状态为 `clear`。
4. 真实 Provider 调用前，由你在隔离账号/profile 中批准小额预算和 Grant。不得把 API key 写入
   项目、pair JSON、截图或评审包。Provider 返回未知结果时停止并对账，不得自动重试。
5. 真实 Provider 的审批、Grant、回执与结算按
   `docs/PRODUCTION_RUN_M2_4_1_TESTING.md` 和 `docs/PRODUCTION_RUN_M2_6_TESTING.md` 执行。

每组创建一份 `m8-visual-pair-evidence-v1` 私有 JSON。它必须包含 `group_id`、`story_id`、
`shared_input_sha256`、`frozen_source_sha256`、十二类 `artifacts`（包括
`visual_agent_run`、`visual_event_log` 与顶层 `production_event_log`），以及
`agent_execution`、`cost` 和 `production`。`production` 必须列出 project/run/stage-run/operation、
HMAC key ID 和 `visual` stage；每个 artifact 都使用证据 JSON 所在目录下的相对路径，并填写实际 `sha256` 和
`bytes`。完整字段约束以 `docs/PRODUCTION_RUN_M8_VISUAL_QUALITY_CONTRACT.md` 为准。

每组产物定稿且 ProductionRun 已到达 `visual/stage_completed` 后，在仍持有该项目外部 HMAC key
的受控终端逐组运行：

```powershell
$env:MANJU_PRODUCTION_HMAC_KEY = '<本次 ProductionRun 使用的外部 HMAC key>'
python tools/m8_visual_evaluation.py attest-pair `
  --evidence-file C:\path\to\private-evidence\story-01-group-01\evidence.json
```

该命令会追加最终签名见证并原子更新 evidence JSON 中 `production_event_log` 的哈希和字节数。
60 组均需各自见证；缺少见证、跨组复用或见证后修改任一产物都会使正式打包失败。
把 60 次命令返回的 `event_hash` 与对应 evidence `production.project_id/run_id` 汇成一个由当前
权威项目重新核对的 JSON 对象，例如 `{"project-a/run-a":"64位事件哈希"}`。该文件应保存在
证据目录之外；若之后发生撤销或追加事件，必须从当前项目重新导出，不能沿用旧映射。

## 二、生成匿名材料

创建 `m8-pairs.json`，60 个 pair 必须各含：

```json
{
  "group_id": "story-01-group-01",
  "story_id": "story-01",
  "source_file": "frozen-sources/story-01.txt",
  "agent_image": "private-evidence/story-01-group-01/agent.png",
  "legacy_image": "private-evidence/story-01-group-01/legacy.png",
  "evidence_file": "private-evidence/story-01-group-01/evidence.json"
}
```

在仓库根目录运行：

```powershell
$env:MANJU_PRODUCTION_HMAC_KEY = '<本次 ProductionRun 使用的外部 HMAC key>'
$env:MANJU_M8_PRODUCTION_HEADS_JSON = Get-Content C:\path\to\current-production-heads.json -Raw
python tools/m8_visual_evaluation.py generate-ab `
  --pairs-file C:\path\to\m8-pairs.json `
  --sample-manifest m8_evaluation\samples.json `
  --public-dir C:\path\to\m8-reviewer-materials `
  --mapping-output C:\path\to\private\m8-mapping.json
```

该 key 只用于验证审批、Grant 和 Provider 调用事件签名，不会写入输出。运行后应从当前终端清除该环境变量。

`source_file` 必须是对应故事的冻结原文字节；选定 storyboard 与镜头上下文放入私有证据，
不能用自行摘要替换评委输入。正式模式的随机 seed 由冻结样本 fingerprint 自动派生，并同时
约束故事内与覆盖类型的 A/B 平衡，请勿自行挑 seed。命令成功后，只把
`m8-reviewer-materials` 发给评委；`m8-mapping.json`、pair 文件和全部生产证据必须隔离保存。

## 三、三人独立盲评

需要三名真实、互不讨论的评委，分别承担 `content`、`visual_production`、`target_user` 视角。
评委不得接触 private mapping、引擎名、Provider、模型、run ID 或生产目录。

分发前记录 `manifest.json` 的 SHA-256 和其中的 `mapping_commitment_sha256`。三份
`m8-visual-review-v2` 评分文件都必须原样写入这两个值。每位评委独立完成全部 60 组：

- 分别给 A、B 的七个维度打 1–5 分；
- 选择 A、B 或 tie；
- 严重错误按 A/B 分别填写布尔值、固定错误代码和至少 10 个字符的可定位说明；
- 使用真实且唯一的 reviewer ID；大小写或 Unicode 变体不能当作不同评委。

由一名操作者复制三份文件、仅修改 ID 或视角，不算独立盲评。建议三人分别提交到只追加目录，
提交后立即记录文件 SHA-256 和时间；任何返工都另存新版本，不覆盖原评分。

## 四、解盲汇总

```powershell
python tools/m8_visual_evaluation.py aggregate `
  --materials-manifest C:\path\to\m8-reviewer-materials\manifest.json `
  --mapping-file C:\path\to\private\m8-mapping.json `
  --review-file C:\path\to\review-content.json `
  --review-file C:\path\to\review-production.json `
  --review-file C:\path\to\review-user.json `
  --contract m8_evaluation\contract.json `
  --sample-manifest m8_evaluation\samples.json `
  --output C:\path\to\m8-visual-summary.json
```

只有完整 20 故事/60 组才能产生 `visual_gate_passed` 或 `visual_gate_failed`。通过要求包括：
故事聚类胜率单侧 95% 下界不低于 60%，来源忠实性和角色一致性配对差值下界不低于 0，
两项绝对均分不低于 3.0，Agent 严重错误不多于 legacy 且不超过全部组的 10%。
`release_eligible` 仍应为 `false`，因为还需要 clean commit、Windows/Linux 全回归和红队关闭。
